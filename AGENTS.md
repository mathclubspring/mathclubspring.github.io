# Математический клуб — инструкции проекта

## Назначение

Это статический сайт математического клуба на Eleventy. Публикация выполняется
через GitHub Pages из ветки `main`.

## Расположение контента

- Обычные страницы: `content/pages/`
- Программы кружков: `content/programs/`
- Материалы: `content/materials/`
- Месячные публикации календаря: `content/events/`
- «Наши мероприятия» и олимпиады: `content/olympiads/`

## Модель материала

Каждый новый материал хранится отдельным Markdown-файлом в
`content/materials/`. Использовать такой front matter:

```yaml
title: Название
slug: english-slug
summary: Короткое описание.
layout: layouts/material.njk
permalink: /materials/english-slug/index.html
section: Логика
tags:
  - логика
grades:
  - "4+"
links:
  - label: Название файла
    url: https://...
```

- `summary` обязателен для новых материалов.
- `grades` — список строк; не преобразовывать возраст или классы в числа.
- `links` всегда имеет формат `label` + `url`.
- Видимый текст внешней ссылки в Markdown должен совпадать с `links[].label`.
- Для незавершённого материала добавлять отдельную строку `[Статья в работе]`.

## Правила изменений

- Не менять утверждённые URL, модель данных, структуру страниц, навигацию или
  дизайн без прямого запроса владельца.
- Не добавлять зависимости, новые сущности, поиск, SEO, RSS, GitHub Actions,
  фильтры и другие функции без запроса.
- Не переписывать авторские тексты без необходимости.
- Не переносить или не удалять контент за пределами явно поставленной задачи.
- Не затрагивать несвязанные пользовательские изменения в рабочем дереве.

## Проверка и публикация

Для изменений сайта:

1. Запустить `npm run build`.
2. Проверить созданную страницу и отсутствие ошибок сборки.
3. Добавить в коммит только файлы задачи и создать понятный коммит.
4. Отправить изменения в `main`.
5. Дождаться успешного запуска GitHub Pages и проверить опубликованную страницу.

Не публиковать изменения, если пользователь попросил только анализ, отчёт,
проектирование или локальную подготовку.
